# TermVR v0.21.10002026111600

`TermVR` `v0.21.10002026111600` (`versionCode` `302100000`) bundles `gvx` `v0.21.10002026111600` (`b14cfd642f46`). It adds live NAT bandwidth limits, block I/O telemetry, OCI image push, and opt-in blob retention for offline `.tar` exports.

## What changed

This release integrates `gvx` `v0.21.10002026111600` across networking, telemetry, and local OCI image workflows. It preserves host lockdown and LAN exposure protections.

### Live NAT bandwidth limits and block I/O telemetry

`TermVR` configures NAT transmit and receive rate caps at launch, on restore, and live over `gvx-ctrl/2`. It also decodes block I/O counters from `sandbox.stats`.

- Added `netTxBps`, `netRxBps`, and `autoPublishAddr` to `NetworkModeConfig`, emitting `--net-tx-bps`, `--net-rx-bps`, and `--auto-publish-addr` for both `run` and `restore`.
- Extended `GvxControlClient` and `SandboxSupervisor.updateResourcesLive` to encode `net_tx_bps` and `net_rx_bps` and decode `block_io` samples (`LiveBlockIoSample`).
- Added TX and RX `Mbps` inputs and `Apply Bandwidth` in `NetworkScreen` (`Backend & WireGuard` tab) to update running NAT containers live.
- Added `NAT Cap` and `Block I/O` read and write counters to the Container Inspector `Stats` tab on `HomeScreen`.

### OCI image push, offline archive export, and runtime sync

Local image actions now push cached images to OCI registries, keep original blobs when requested, and pass `-i` to `rungv image load`.

- Added `CatalogRepository.pushImage` and the `Push` dialog in `CatalogScreen` (`Local Images` card) running `rungv image push --host-dns 127.0.0.1:<port>`.
- Added opt-in `Keep original blobs` (`-keep-blobs`) in `CatalogScreen` for `pull` and `image load`, enabling offline `image save` exports.
- Fixed `CatalogRepository.buildImageLoadArgs` to pass `-i <tarPath>` to `rungv image load`.
- Bundled `gvx` `v0.21.10002026111600` (`b14cfd642f46`), including live NAT bandwidth shaping, block I/O telemetry, `-keep-blobs`, `image push`, and the `gvx-oci/v1.0` registry `User-Agent`.

## Reproducible build and verification

GitHub Actions builds every release artifact offline from pinned commits in `scripts/source-lock.json` and verifies clean-room reproducibility before signing. All shared libraries align `PT_LOAD` segments to at least `16384` bytes (`16 KB`), and GitHub attaches `SLSA` v1.0 Build Level 2 provenance.

Run these commands to verify downloaded APKs and their v2 and v3 signatures.

```bash
sha256sum -c SHA256SUMS
apksigner verify --verbose --print-certs TermVR-v0.21.10002026111600-arm64-v8a.apk
```

Run `./scripts/verify-reproducible-apk.sh` to verify F-Droid build reproducibility from tag `v0.21.10002026111600`.

```bash
./scripts/verify-reproducible-apk.sh --signed-apk TermVR-v0.21.10002026111600-arm64-v8a.apk --abi arm64-v8a
```

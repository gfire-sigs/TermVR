# TermVR v0.24.10002026112300

`TermVR` `v0.24.10002026112300` (`versionCode` `302400000`) bundles `gvx` `v0.24.10002026112300` (`e4e6b7b8b695`). It updates the embedded runtime with user-data volume defaults and working-directory resolution for relative executables, and aligns `TermVR` volume storage via `XDG_DATA_HOME`.

## What changed

This release updates the embedded runtime to upstream `gvx` `v0.24.10002026112300` and preserves the persistent `<filesDir>/gvx-store/gvx/volumes/` layout across fresh and upgraded installs. All existing container profiles, workspaces, and persistent `ext4lite` volumes stay compatible.

### Runtime upgrade to `gvx` `v0.24.10002026112300`

Upstream `gvx` `v0.24.10002026112300` (`e4e6b7b8b695`) builds on `gVisor` `release-20261123.0` (`83df8eae069e`) with volume-storage isolation and relative executable resolution improvements.

- Upgraded pinned `gvx` runtime to `v0.24.10002026112300` (`e4e6b7b8b695`), moving default named volume storage out of cache directories with automatic legacy migration and adding `-volume-dir` and `GVX_VOLUME_DIR` controls (`gvx#261`).
- Included VFS-backed working-directory resolution for relative guest executables and relative or empty `PATH` entries while preserving symlink names (`gvx#262`).
- Updated `CheckpointController.DEFAULT_GVX_VERSION`, `scripts/source-lock.json`, `gradle/libs.versions.toml`, `fdroid/dev.gfire.termvr.yml`, and bundled license notices.

### Persistent volume storage alignment (`XDG_DATA_HOME`)

Upstream `gvx` `v0.24` resolves default named volumes on Android under `$XDG_DATA_HOME/gvx/volumes` rather than `$XDG_CACHE_HOME/gvx/volumes`.

- Updated `GvxCommandBuilder.buildHostEnvironment` to export `XDG_DATA_HOME = <filesDir>/gvx-store` alongside `XDG_CACHE_HOME`.
- Verified that `librungvx.so` named volume storage remains at `<filesDir>/gvx-store/gvx/volumes/` on both fresh installs and upgrades, matching `GvxCommandBuilder.volumeImageFile` and `CatalogRepository`.
- Updated `GvxCommandBuilderTest` and `docs/designs/0001-termvr-system-design.md` Section 15.1.

## Reproducible build and verification

GitHub Actions builds every release artifact offline from pinned commits in `scripts/source-lock.json` and verifies clean-room reproducibility before signing. All shared libraries align `PT_LOAD` segments to at least `16384` bytes (`16 KB`), and GitHub attaches `SLSA` v1.0 Build Level 2 provenance.

Run these commands to verify downloaded APKs and their v2 and v3 signatures.

```bash
sha256sum -c SHA256SUMS
apksigner verify --verbose --print-certs TermVR-v0.24.10002026112300-arm64-v8a.apk
```

Run `./scripts/verify-reproducible-apk.sh` to verify F-Droid build reproducibility from tag `v0.24.10002026112300`.

```bash
./scripts/verify-reproducible-apk.sh --signed-apk TermVR-v0.24.10002026112300-arm64-v8a.apk --abi arm64-v8a
```

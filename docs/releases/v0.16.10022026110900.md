# TermVR v0.16.10022026110900

`TermVR` `v0.16.10022026110900` (`versionCode` `301600020`) upgrades the bundled `gvx` runtime to `v0.16.10022026110900` (`4f7bbd5ff889`). It improves CJK soft-keyboard input, touch selection, SAF workspace saves, live port conflict checks, DNS roaming, and 16 KB `arm64` JIT workloads.

## What changed

This release pairs `gvx` kernel fixes (`#203`, `#204`, and `#205`) with storage, terminal UI, and network supervisor updates. Every section below summarizes the user-visible changes across terminal input, storage bridges, network controls, and 16 KB `arm64` execution.

### Hangul/CJK input, touch selection, and bracketed paste

Soft keyboards now keep full Korean, Japanese, and Chinese language modes active without leaking password hints. Viewport touch handling also separates TUI mouse tracking from long-press text selection and neutralizes pasted escape sequences.

- Removed `TYPE_TEXT_VARIATION_VISIBLE_PASSWORD` from `TerminalInputConnection` and added `IME_FLAG_NO_PERSONALIZED_LEARNING` over the 64-space sentinel buffer.
- Flushed mid-preedit `CTRL`, `ESC`, and special-key chords cleanly and translated Korean 2-beolsik `CTRL` and `ALT` jamo chords.
- Applied initial grid sizes immediately, coalesced resize bursts with a `48 ms` trailing debounce, and flushed resizes immediately on teardown.
- Added a long-press text-selection escape hatch inside mouse-tracking TUIs (`tmux`, `htop`, and `nvim`) while keeping 1-finger `SGR 1006` wheel scrolling.
- Stripped `ESC`, `CSI` (`0x9B`), and `NUL` control bytes during bracketed paste while preserving valid UTF-8 multibyte sequences and normalizing `\r\n` line endings.

### SAF workspace saves and single-writer volume locks

External Android code editors now preserve executable script modes and append semantics when saving files inside `/workspace`. `Files` also streams large archive imports without heap spikes and explains active `ext4lite` mount locks clearly.

- Preserved POSIX file permissions (such as `0755` scripts) and `"wa"` / `"rw"` file contents across atomic `.termvr.tmp` saves in `TermVrDocumentsProvider`.
- Queried `OpenableColumns.DISPLAY_NAME`, bounded staging filenames within `255` UTF-8 bytes, and streamed `64 KiB` SAF chunks directly to disk.
- Paused offline volume helper launches while containers run or hold checkpoints to protect single-writer `ext4lite` filesystems.
- Added `Open Workspace`, `Stop Container`, and dual-pane `Discard Checkpoint` actions on locked volume cards in `Files`.

### Port conflicts, DNS TCP fallback, and child-process status

`Network` and `Home` now catch host port collisions before restarting running sandboxes and keep DNS working across Wi-Fi handoffs. Host readiness cards also display live child-process counts against Android's 32-process cap.

- Added pre-bind self, cross-profile, and host socket conflict checks (`PortConflictDetector`) with automatic rule rollback when a live port apply fails.
- Enforced a strict `64 KiB` size limit and sanitized `OpenableColumns.DISPLAY_NAME` metadata when importing WireGuard `.conf` files through SAF.
- Added RFC 1035 and EDNS0 truncation (`TC=1`) handling with active-network TCP DNS fallback in `LoopbackDnsProxy`, plus reliable Wi-Fi LAN reconfirmation.
- Surfaced live `running · X/32 procs` indicators and actionable Android 12+ `SIGKILL` (`137` / `-9`) child-process remediation notices on `Home`.

### 16 KB arm64 JIT engines and pseudo-terminal job control

`gvx` `v0.16.10022026110900` (`#203`, `#204`, and `#205`) hardens `arm64` 16 KB sub-block fault emulation and `devpts` master hangup signaling. Node.js V8 JIT compilation, nested `script` sessions, and `tmux` pane exits now run cleanly on 16 KB `arm64` hosts.

- Untagged `arm64` Top-Byte-Ignore (`TBI0`) fault addresses, decoded unscaled `STLUR` stores, and invalidated split 4 KB composite instruction caches in `gvx` (`#203`).
- Woke `devpts` replica readers on master hangup (`EPOLLHUP`) or `TCSETS` `VMIN` updates and routed master `TIOCSCTTY`, `TIOCGPGRP`, and `TIOCSPGRP` job-control ioctls (`#205`).

## Reproducible build and verification

GitHub Actions builds every release APK offline from pinned commits in `scripts/source-lock.json` and verifies clean-room reproducibility before signing. All shared libraries align `PT_LOAD` segments to at least `16384` bytes (`16 KB`), and GitHub attaches `SLSA` v1.0 Build Level 2 provenance.

Run these commands to verify downloaded APKs and their v2 and v3 signatures.

```bash
sha256sum -c SHA256SUMS
apksigner verify --verbose --print-certs TermVR-v0.16.10022026110900-arm64-v8a.apk
```

Run `./scripts/verify-reproducible-apk.sh` to verify F-Droid build reproducibility from tag `v0.16.10022026110900`.

```bash
./scripts/verify-reproducible-apk.sh --signed-apk TermVR-v0.16.10022026110900-arm64-v8a.apk --abi arm64-v8a
```

# TermVR v0.17.10002026110900

`TermVR` `v0.17.10002026110900` (`versionCode` `301700000`) upgrades the bundled `gvx` runtime to `v0.17.10002026110900` (`e410633f24cf`). It adds online `ext4lite` space reclamation, volume compaction, copy-on-write (`CoW`) volume branching, and multi-container shared Git worktree projects.

## What changed

This release pairs `gvx` `v0.17.10002026110900` storage capabilities with volume management, profile cloning, and Storage Access Framework (`SAF`) bridges in `TermVR`. Every section below summarizes the user-visible changes across `Files`, `Home`, `TermVrDocumentsProvider`, and the sandbox supervisor.

### Online ext4lite auto-shrink and offline volume compaction

`ext4lite` volumes and persistent rootfs images now release unused disk blocks back to Android storage while containers run. Users can also compact stopped `ext4lite` images directly from `Files`.

- Enabled online hole punching and background block reclamation in `gvx` `v0.17.10002026110900` (`ext4lite`) so deleted guest files reduce host `st_blocks` allocation automatically.
- Reported both physical host allocation (`AllocatedBytes`) and logical image capacity (`SizeBytes`) in `Files > Volumes` cards.
- Added offline `Compact` actions in `Files > Volumes` (`compactExt4LiteVolume`) for stopped, uncheckpointed `ext4lite` volumes and persistent rootfs images.

### Copy-on-write volume branching

Multiple running containers can now share one read-only `ext4lite` base volume while writing isolated changes to separate upper overlays.

- Added `OVERLAY_EXT4LITE` volume mount support in `GvxCommandBuilder` and `SandboxSupervisor` using `overlay_ext4lite` (`lower` read-only base image plus persistent `ext4lite` upper or RAM scratch upper).
- Displayed `Shared (RO)` badges on active base volumes in `Files > Volumes` and blocked destructive edits while child branches hold mounts or checkpoints.
- Added branch creation and `Branch Sandbox` workflows in `Home` and `Files` so users fork environments without duplicating base disk images.

### Multi-container shared Git worktree projects and SAF

Concurrent containers can now collaborate on one shared bare Git repository with per-container worktrees while preserving Android `SAF` editor access.

- Added `GitWorktreeManager` (`core:data`) to manage host-backed bare repositories (`/git/<project>.git`) and per-container worktrees (`/workspace`) with `.gvx_meta` mode preservation.
- Added `Git Projects` management in `Files` and `Home` profile setup to attach multiple running containers on distinct branches (`wt/...`) simultaneously.
- Exposed `TermVR Git Worktrees` in `TermVrDocumentsProvider` for external Android editors with atomic `.termvr.tmp` saves and POSIX `0755` mode preservation, skipping writes while the owning container is frozen.

## Reproducible build and verification

GitHub Actions builds every release APK offline from pinned commits in `scripts/source-lock.json` and verifies clean-room reproducibility before signing. All shared libraries align `PT_LOAD` segments to at least `16384` bytes (`16 KB`), and GitHub attaches `SLSA` v1.0 Build Level 2 provenance.

Run these commands to verify downloaded APKs and their v2 and v3 signatures.

```bash
sha256sum -c SHA256SUMS
apksigner verify --verbose --print-certs TermVR-v0.17.10002026110900-arm64-v8a.apk
```

Run `./scripts/verify-reproducible-apk.sh` to verify F-Droid build reproducibility from tag `v0.17.10002026110900`.

```bash
./scripts/verify-reproducible-apk.sh --signed-apk TermVR-v0.17.10002026110900-arm64-v8a.apk --abi arm64-v8a
```

# TermVR v0.18.10002026111600

`TermVR` `v0.18.10002026111600` (`versionCode` `301800000`) upgrades the bundled `gvx` runtime to `v0.18.10002026111600` (`a55326e735cb`) and syncs upstream gVisor to `release-20261116.0` (`83282de1f21f`). It adds guest loopback fallback for published ports, fixes an `ext4lite` and `hostfs` rename deadlock, improves DNS and NAT TCP error semantics, and refreshes gallery screenshots.

## What changed

This release brings `gvx` `v0.17.10012026111600` through `v0.18.10002026111600` into `TermVR` alongside updated F-Droid Fastlane screenshots. Every section below summarizes the user-visible runtime and storage fixes.

### Runtime networking and gVisor release-20261116.0

Inbound port forwarding, guest DNS resolution, and outbound NAT TCP dials now match standard Linux and Docker networking behavior more closely.

- Added guest loopback (`127.0.0.1`) fallback for inbound `-p` port forwarders (`gvx#219`), allowing host browsers and clients to reach guest servers bound only to `localhost`.
- Bundled opt-in `--auto-publish` dynamic loopback port publishing in `librungv.so` (`gvx#218`, `gvx#220`) while keeping host lockdown active.
- Aligned the `gvx` DNS relay with Docker Engine (`gvx#208`, `gvx#215`): forward TCP DNS queries over upstream TCP, answer internal names authoritatively, and return empty `NOERROR` for `AAAA` without an IPv6 route.
- Classified outbound NAT TCP dial failures (`gvx#206`) so timeouts yield `ETIMEDOUT` and unreachable hosts return ICMPv4 `EHOSTUNREACH` or `ENETUNREACH` instead of unconditional resets.

### Storage locking and volume stability

`ext4lite` and `hostfs` drivers now prevent lock-order deadlocks under concurrent container builds and reuse held blocks cleanly during mapped writes.

- Replaced `fs.mu` with a leaf `ancestryMu` lock for `IsDescendant` and `PrependPath` in `ext4lite` and `hostfs` (`gvx#209`), fixing mount-propagation deadlocks during parallel renames.
- Separated held-space reuse and volume growth in `ext4lite` (`gvx#214`, `gvx#216`) so mapped write-backs wait for active hole punches and flush held space without unnecessary sequential growth.
- Refreshed gallery screenshots in `README.md` and added Fastlane F-Droid phone screenshots.

## Reproducible build and verification

GitHub Actions builds every release APK offline from pinned commits in `scripts/source-lock.json` and verifies clean-room reproducibility before signing. All shared libraries align `PT_LOAD` segments to at least `16384` bytes (`16 KB`), and GitHub attaches `SLSA` v1.0 Build Level 2 provenance.

Run these commands to verify downloaded APKs and their v2 and v3 signatures.

```bash
sha256sum -c SHA256SUMS
apksigner verify --verbose --print-certs TermVR-v0.18.10002026111600-arm64-v8a.apk
```

Run `./scripts/verify-reproducible-apk.sh` to verify F-Droid build reproducibility from tag `v0.18.10002026111600`.

```bash
./scripts/verify-reproducible-apk.sh --signed-apk TermVR-v0.18.10002026111600-arm64-v8a.apk --abi arm64-v8a
```
